# Sample seed data

Run the optional seed after applying migrations, from `backend`:

```powershell
python -m app.seed
```

On an empty product table, the command adds **30 products**, each with a description, decimal INR price, whole-number quantity, shared category, and HTTPS image URL. IDs and creation dates are generated by PostgreSQL. The dataset includes in-stock, low-stock, and out-of-stock products.

The data is bundled in `backend/app/seed_products.json`; the command does not fetch an API, download images, or require image hosts to be available. Images are loaded by the browser, with the existing fallback if a URL becomes unavailable. Sample image URLs use [DummyJSON's product image CDN](https://dummyjson.com/docs/products) and [Unsplash](https://unsplash.com).

## Existing data and repeated execution

The command checks the entire product table, including soft-deleted rows. If any row exists, it prints `Skipped: products already exist.` and makes no catalog changes. This also means an existing 12-product catalog is not automatically expanded or overwritten by this version.

A successful fresh seed prints `Added 30 demo products.` Repeating the command leaves the count unchanged. It does not restore deleted products or change user-edited values.

## Transaction and category behavior

The complete dataset is validated using the product API schema before any categories or products are inserted. Categories are resolved once per distinct name through the shared case-insensitive registry.

All inserts occur in one transaction. Errors roll back category creation and product inserts together. A PostgreSQL transaction advisory lock serializes simultaneous seed commands before the empty-table check.

Seeding is never run automatically during application startup. No schema migration is required for this dataset change.

## Verification

Backend regressions check dataset validity, all 30 image associations, category reuse, generated fields, idempotency, nonempty/deleted-data protection, command output, rollback after a failure, and API operations on seeded records. CI also runs the seed command twice after the PostgreSQL tests.

A browser regression loads the same bundled 30-product dataset through API fixtures and checks image rendering, three-page pagination, details, editing, category selection, deletion, and search. It serves deterministic local images during the test so external hosts cannot make the UI test flaky.
